# Grounded discovery implementation checkpoints

Accepted Phase 2 baseline: one grounded search pass, application-validated source observations, then constrained selection of candidate keys; at most three model calls per request. Both find-material and goal-only branches require explicit source confirmation. Search suggestions never count as retained learning content. No invented external URL fallback.

1. Define provider-independent search/selection contracts and semantic validators. Implement Google search behind Vercel AI SDK 7.0.133 / Google provider 4.0.92, matching installed tool types. Consume only SDK URL-source records as citations; ignore model prose URLs. Keep a bounded candidate inventory and fail explicit overflow. Use one provider-executed search step, then a separate schema-constrained key selection with no tools and one repair at most. Require a durable reservation callback for every call. Add mock-model tests before wiring paid execution.
2. Observe cited URLs through the existing SSRF-safe, DNS-pinned public transport with explicit redirect provenance and bounded reads. Resolve grounding redirect URLs through that boundary, never ordinary fetch. Reject inaccessible/unsupported sources with per-candidate failures. Validate actual metadata independently of the model. Retain private discovery evidence and selected candidate references. Preserve bounded provider search-entry attribution as opaque content; the later UI must use an isolated renderer, never insert provider HTML into the application DOM.
3. Connect owned commands, budgets, jobs/checkpoints, recovery and explicit source selection for find-material/goal branches. Reuse existing acquisition operations after confirmation; a discovered source remains unacquired until actual content is retained. Add an explicit AI-authored-guide alternative only if desired by the user, labeled generated and citation-free. No silent substitution.
4. Validate fixture journeys, source failures, malformed grounding/selection, cancellation, budget exhaustion, stale revisions and durable restart. Live grounding requires configured credentials and a narrowly scoped approved smoke; fixture results are not live verification.

Official reference: https://ai-sdk.dev/providers/ai-sdk-providers/google#google-search (v7 documentation checked against installed googleSearch tool and SDK sources types on 2026-10-10). Current documentation includes newer model examples; retain the approved registry model/default and installed package pins. No provider upgrade or legacy AI migration is needed.

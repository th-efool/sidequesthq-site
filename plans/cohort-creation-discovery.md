# Grounded discovery implementation checkpoints

Durable integration uses existing owner/CAS/job/event repositories, 90-second global model slots, the existing hourly owner budget and exactly three model reservations per discovery job. A 15-minute task deadline covers one 60-second search, bounded selection/repair and up to twenty 30-second metadata observations. Snapshot discovery state is separate from material acquisition. Shared discovery schemas and the existing storage reference contract were extracted into dependency-free modules to prevent a contracts/materials import cycle; existing material imports remain compatible through a re-export. Intermediate observation pins detach transactionally when a newer accepted checkpoint replaces them. Real SQL validation and confirmation UI follow this foundation commit.

Current implementation checkpoint: retain immutable search evidence before observing citations; checkpoint each observed/failed citation and the final validated selection. Bind receipts to owner/draft/request/input/intent fingerprints. Resume must validate the referenced receipt hierarchy and processed citation prefix, reuse successful metadata and avoid another search/selection call after its accepted checkpoint. Known work counts come from actual processed citations. Keep source failures explicit; no retained-material claim and no silent guide fallback. Add focused retained-session tests before durable queue integration.

Accepted Phase 2 baseline: one grounded search pass, application-validated source observations, then constrained selection of candidate keys; at most three model calls per request. Both find-material and goal-only branches require explicit source confirmation. Search suggestions never count as retained learning content. No invented external URL fallback.

# Phase 3B.3 — material acquisition, bounded implementation plan

Baseline: durable creation jobs/storage/retention implemented; Mongo live connection remains blocked by ENOTFOUND. Existing MaterialSource, SourceLocation and ExtractedContent contracts and private artifact storage are reused. Legacy GitHub/Notion importers do not retain trustworthy complete content; they will not be used as extraction substitutes.

## First milestone: retained UTF-8 text and Markdown

1. Extend the foundation contracts with validated manifests, extraction artifacts, segments and full coverage/provenance. Reuse opaque storage references; source bodies stay out of draft snapshots.
2. Implement deterministic UTF-8 decoding and offset-preserving segmentation. Retain raw source bytes, preserve headings/code, never execute HTML/code, reject invalid encoding/empty or binary input and the approved 1 MiB extracted-text limit without truncation.
3. Add an acquisition service that reads an already owned retained upload and writes an immutable extraction artifact through existing storage. Return a proposal for the future fenced job checkpoint; do not mutate navigation or pin unaccepted results.
4. Test exact content/coverage, multibyte offsets, deterministic identities, malformed contracts, byte limits, abort and persistence failures using storage mocks. Run typecheck/scoped tests/lint, inspect diff, commit separately, update the checkpoint.

This milestone does not claim an end-user material flow. Subsequent bounded milestones connect source manifests to durable draft commands/jobs, then upload/paste/drop endpoints/screens, then external acquisition and grounded discovery with user-scoped connectors. Worker operation generalization must precede background acquisition wiring; recommendation jobs remain unchanged here. No processing/review/publication or Phase 4 visual implementation.

## Next milestone: durable text acquisition boundary

Add an authenticated draft command selecting an already retained owned text upload. Persist source selection and queue an acquire_text operation in the existing creation_jobs transaction. Extend claimed job inputs/checkpoints with a discriminated operation contract; preserve recommendations and their deadline. Execute text acquisition through the existing runner/worker, checkpoint the manifest and pin immutable references under owner/input/lease fencing, then accept the extraction projection into the snapshot. Cancellation/failures retain selected raw material; retry uses a new request and revision. Default material fields decode old snapshots without a database migration. Recommendation intent revisions remain valid across material-only input changes; new queries clear materials. Validate transitions, ownership, stale results, restart/checkpoint recovery and repository operations. No upload HTTP/UI or external adapters in this milestone.

## Upload/paste/drop milestone

Add a Node streaming upload route authorized by the existing draft owner and captured baseRevision. Accept raw text/Markdown bytes, not buffered multipart JSON; file selection/drop and pasted text send the same Blob request. Enforce the 1 MiB text scope within the existing 25 MiB/file and 100 MiB/draft storage boundaries, actual streaming limits, a request deadline and cancellation. Completed upload acknowledgements contain only opaque references. Queue acquisition separately against the captured draft revision; interrupted/lost/stale acknowledgements remain reclaimable and never silently select material for a newer intent.

Add one functional have-material panel under the existing starting-point screen. Show file/paste modes, upload cancellation, actual pending/ready/failed sources and acquisition retry/cancel through existing commands/events. Keep unsupported find/goal branches explicit. Reuse current layout primitives; no reference geometry tuning. Validate auth/ownership/revision/size/media/stream interruption and UI selection/drop/paste/reload/failure paths. Commit API, client wiring and tests in meaningful batches.

## Source recovery milestone

Add a bounded remove_material command guarded by owner, revision and idle starting-point state. Remove only the chosen source/extraction, advance inputRevision, preserve other sources and intent, and release detached unpublished storage pins atomically with the snapshot event. Share the existing enqueue pin-detachment rule with ordinary draft CAS; never delete bytes synchronously or release published/shared references.

Expose remove and replacement controls in the same material step. Replacement reuses acquire_text with the existing material ID, retaining the old selection until the owned new upload is acknowledged and CAS enqueue succeeds. Permit replacement at the twenty-source limit only for an existing source ID. Failed upload/stale attachment preserves the original selection; successful replacement invalidates only that source extraction. Validate guards, authorization, conflicts, shared/published pin protection, full-selection replacement and client recovery. No new schema, external adapters, AI calls or later phases.

## Controlled web fetch foundation

Legacy importWebArticle creates reference metadata rather than retained content, so do not reuse it as extraction. Phase 2 requires HTTPS/public destinations, DNS and redirect validation, inert DOM/Readability extraction, private retained bytes and provenance. This bounded milestone implements only controlled HTTPS fetching and retained raw-response receipts; DOM extraction, durable web commands and UI wiring follow next.

Use Node 24 HTTPS with a fresh agent/custom lookup pinned to a validated DNS result, normal TLS hostname verification, no shared cookies/credentials/proxies and no automatic redirects. Validate every address and redirect; deny private/reserved addresses, credentials, nonstandard ports and downgrade URLs. Three redirects, thirty-second overall deadline, 16 KiB headers, 25 MiB raw-body ceiling within existing storage quota. Request identity encoding; reject compressed responses explicitly rather than leaving decompression limits implicit. Accept HTML/plain/Markdown in UTF-8/ASCII, require complete nonempty bytes and accurate declared lengths. Retain actual streamed bytes through MaterialBlobStore; receipts carry source URL, final URL, redirect chain, timestamp, checksum/reference and input revision, never a fake extraction or ready source. Test all boundaries with injected DNS/transport/storage; no live paid requests or production state changes.

Implementation uses Node 24 http.request custom lookup and net.BlockList addSubnet/check, supported by the repository Node >=24 <25 target. Official references: https://nodejs.org/docs/latest-v24.x/api/http.html and https://nodejs.org/download/release/v24.13.0/docs/api/net.html. Do not use Node 26-only BlockList.PRIVATE_RANGES/addCIDRs APIs.

## Retained article extraction milestone

Promote already installed jsdom 29.1.1 into pinned runtime dependencies and add pinned @mozilla/readability 0.6.0 (official Node integration). Use jsdom without script execution or resource loading; never expose HTML output to React. Bound DOM elements to 20,000 and raw HTML parsing to 2 MiB as an explicit technical scope error (raw retention still supports 25 MiB). Reject login/JS-only/empty/unsupported content. Readability selects main article; receipt/raw bytes retain the full page. Artifacts explicitly distinguish complete article-text coverage from whole-response coverage; no false claim that navigation/ads were extracted. Plain/Markdown response text is retained whole. Enforce 1 MiB extracted UTF-8 text, stable parser/version and surrogate-safe UTF-16 anchors, external origin, final/requested URLs and retained checksums.

Reuse text segmentation without fabricating a source reference. Web extraction verifies the owned retained raw receipt/ref/media/checksum before parsing and writes an immutable extraction artifact, returning a manifest proposal only. Test malformed provenance, HTML scripts/resources/login/JS shells, exact text coverage, Unicode, scope limits, cancellation and storage failures. Commit adapter/contracts/dependencies with focused validation and update checkpoint before durable web integration.

## Durable web integration milestone

Extend existing acquire_text architecture with acquire_web, normalized safe HTTPS commands, shared single-unit guards and retained-response intermediate checkpoints. Pin raw bytes and receipt artifact under owner/input/lease fencing before extraction; restart from receipt without network fetch. Validate final manifest/parser/checksum/fingerprints and pin extraction before accepting ready state. Snapshots retain opaque materialRefs for raw/receipt/extraction so replacement/removal/new intent can release unused unpublished references even after failure/cancellation. Keep application state authoritative and fail stale results. Reuse persistent budgets, replay, worker concurrency and cancellation; no new tables/queue. Web deadline 120 seconds covers bounded fetch, retained reads and DOM work. Add functional URL mode/retry/replacement in the same material panel. Validate restart, stale revisions/lease, foreign refs, actual readiness, ownership and UI persistence. Then continue remaining acquisition adapters in subsequent checkpoints.

## Retained PDF foundation

Pin pdfjs-dist 6.4.299, compatible with Node 24, following Mozilla's Node getDocument/getTextContent example. Parse only owned retained bytes; never pass PDF URLs to the library or request images/scripts/annotations. Run PDF.js in a separate Node worker thread with 128 MiB old-generation limit and a 45-second hard deadline; abort terminates the parser thread rather than relying on checks between CPU-bound operations. Worker module uses built-in Node and explicit PDF.js module resolution, not application state or credentials.

Validate PDF signature/checksum/25 MiB before parse, 200 pages before extraction, full per-page text and 1 MiB aggregate UTF-8 output during extraction. Blank/image-only pages require OCR or a text alternative; do not silently skip pages or fabricate text. Password/encrypted/malformed documents fail explicitly. Retain page text, page spans, surrogate-safe segments and page provenance; raw bytes stay private. Application-independent parser tests include real generated two-page PDF bytes, malformed/scanned/page-limit cases and cancellation. Service writes immutable proposals through existing artifact storage; upload/job wiring is a subsequent checkpoint.

## Durable PDF integration

Extend the existing upload endpoint with application/pdf and a 25 MiB type-specific streaming ceiling while preserving the 1 MiB text limit. Add acquire_pdf through the same shared command, CAS/deduplication service, persistent job repository and worker runner. Pin only an owned ready PDF upload, then validate and pin a pdf-extraction checkpoint before accepting ready state; reuse materialRefs, removal/replacement, retention, cancellation and replay. Give PDF jobs a 120-second deadline to cover retained reads, bounded parser and storage. Add PDF file/drop selection, matching limits, kind-preserving retry and clear page-text/OCR scope in the existing panel. Test upload size/media boundaries, state guards, restart without re-extraction, stale manifests, ownership/CAS and client reload. No new schema, worker infrastructure or later-stage processing.

## YouTube metadata foundation

Legacy video import catches API failures and supplies invented defaults such as twelve-minute duration. Reuse its pure ID helpers only after strict HTTPS/exact-host/path/ID validation; isolate legacy import behavior. Add a bounded Data API metadata reader for public processed videos and paginated playlists, without treating metadata as extracted learning content. Use fixed Google API endpoints, no redirects/cookies, sanitized errors, 30-second operation deadline and 2 MiB JSON response ceiling. Respect 100-unit scope; duplicate/unavailable videos, repeated pagination tokens and oversized playlists fail explicitly rather than silently truncating. Playlist enumeration preserves real item order and metadata ETags. No transcript scraping or paid AI call in this milestone.

Official API references: https://developers.google.com/youtube/v3/docs/videos/list and https://developers.google.com/youtube/v3/docs/playlistItems/list. Installed ai 7.0.133 / @ai-sdk/google 4.0.92 bundled docs confirm file-part YouTube support; current https://ai-sdk.dev/providers/ai-sdk-providers/google also documents it. Current examples use newer model IDs; retain the existing model registry. Google's https://ai.google.dev/gemini-api/docs/video-understanding restricts YouTube input to public videos, more conservatively than the SDK's public/unlisted wording. Future observation uses one canonical public video per bounded structured call, explicitly AI interpretation with estimated time anchors, never a fabricated transcript or metadata-only success. Durable observation budgets/artifacts/checkpoints and UI selection follow this foundation.

## Bounded video observation foundation

Introduce a provider-independent MaterialObservation interface and small structured VideoObservationProposal contract. One canonical public video per Vercel SDK file-part call; no tools, autonomous loop or arbitrary downloads. Validate ordered nonoverlapping ranges against authoritative metadata duration, nonempty educational observations, explicit limitations and provider inability. Model-generated content and timestamp estimates remain labeled; application derives gap ranges and never claims exhaustive/transcript coverage. No model-produced IDs, URLs, navigation or permissions are accepted.

Use the existing LanguageModel registry injection and required beforeCall reservation callback, with zero SDK retries, one schema repair at most, 90-second total adapter deadline, 12,000 output tokens and 200 observation sections. Validate schema and semantic bounds; truncated/provider-inaccessible output must fail explicitly. Persisted budget integration and artifacts are separate next checkpoints; this adapter is not exposed to users before those exist. Routine tests use MockLanguageModelV4 with no paid calls, including canonical URL rejection, schema repair, duration/order/inability, abort, sanitized provider errors and reservation/release failures. Preserve legacy Google services.
